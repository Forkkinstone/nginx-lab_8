1. Цель работы
Изучение инструментов управления зависимостями (Composer) и внедрение автоматизированного тестирования (PHPUnit) в веб-приложение, использующее Docker-контейнеры.


2. Ход работы
2.1. Инициализация Composer
Был создан файл composer.json для управления внешними библиотеками. В проект добавлены следующие зависимости:

php-amqplib/php-amqplib — для работы с очередями RabbitMQ.

phpunit/phpunit — фреймворк для модульного тестирования.

guzzlehttp/guzzle — HTTP-клиент для интеграционных тестов.

{
    "require": {
        "php-amqplib/php-amqplib": "^3.0"
    },
    "require-dev": {
        "phpunit/phpunit": "^9.0",
        "guzzlehttp/guzzle": "^7.0"
    },
    "autoload": {
        "psr-4": {
            "App\\": ""
        }
    }
}

2.2. Реализация Unit-тестов и Mock-объектов
Для класса QueueManager разработан набор тестов:

testIsQueueManagerCanBeCreated: Проверка успешной инициализации объекта класса.

testPublishWithMock: Тестирование метода отправки сообщения с использованием Mock-объекта. Это позволило протестировать логику метода publish в изоляции, без необходимости подключения к реальному серверу RabbitMQ.

2.3. Интеграционное тестирование
С помощью библиотеки Guzzle реализован тест HttpTest.php. Он имитирует HTTP-запрос от PHP-контейнера к Nginx-контейнеру для проверки доступности главной страницы (index.php) и корректности ответов сервера (статус-код 200).

2.4. Исправление деструктора
В ходе тестирования была выявлена ошибка при уничтожении Mock-объектов. В класс QueueManager.php добавлена проверка наличия активных ресурсов перед вызовом close(), что повысило стабильность кода.


3. Результаты тестирования
Запуск тестов производился внутри Docker-контейнера командой:
